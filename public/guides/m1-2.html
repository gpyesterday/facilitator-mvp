💡 더 깊이 묻기
Q1. 데이터가 100개에서 10만 개로 늘면 지금 요약 API는 어떤 문제가 생길까요?
모든 레코드를 매번 읽어 계산하면 지연·읽기 비용이 커질 수 있습니다. 날짜 범위 필터, 집계 저장/캐시, 페이지네이션 등을 검토하고, 정확성과 최신성 사이의 기준을 설명하도록 유도합니다.
Q2. 요약을 프롬프트에 넣는 방식이 항상 충분할까요?
요약은 빠르고 단순하지만 상세 레코드 근거가 사라질 수 있습니다. 구체적 질의에 상세 조회가 필요한 경우 도구 호출/검색으로 확장하거나 요약 범위를 조정하는 판단을 토론합니다.

확인 순서
브라우저 요청의 Origin과 백엔드 ALLOWED_ORIGINS를 비교합니다. 로컬 개발 주소와 실제 Vercel 도메인을 필요한 범위만 허용하고, 배포 후 API 재배포 및 네트워크 요청을 확인하세요. 자격 증명 사용 시 와일드카드(*) 설정은 피합니다.
콜드스타트 안내
Render 무료 서비스는 유휴 후 첫 요청에 지연이 생길 수 있습니다. 화면에 “서버를 깨우는 중일 수 있어 잠시 기다려 주세요”를 표시하고, 로딩 상태를 유지하며 재시도 안내를 제공합니다. 반복 호출이나 무한 재시도는 피하세요.
키·프로젝트 설정 확인
Render 환경 변수의 Firebase 서비스 계정 JSON/파일 경로, 프로젝트 ID, Firestore 활성화 여부를 확인합니다. 키 값은 로그·README·브라우저 응답에 출력하지 말고 오류 응답에는 안전한 설명만 제공합니다.
API 계약을 확인하세요
대화 목록이 id를 반환하는지, 선택 시 상세 조회가 messages 전체를 돌려주는지 확인합니다. 상세 GET endpoint를 구현하거나 목록 API 응답에 messages 포함을 분명히 정의하고, 프론트가 동일한 필드명을 사용하는지 확인하세요.
요약·프롬프트·검증 흐름 점검
summary 응답을 직접 확인하고, 시스템 프롬프트에 최신 요약이 실제로 전달되는지 점검합니다. 데이터가 없을 때 추측하지 말고 부족함을 알리게 하며, 핵심 숫자를 포함한 질문으로 답변을 검증하세요. 프롬프트만으로 정확성을 보장할 수 없다는 점도 설명합니다.
최소 운영 안전장치
키는 서버 환경 변수로만 관리하고 요청 길이·호출 횟수·모델 토큰 한도를 제한합니다. 입력 스키마와 길이를 검증하고, 프롬프트 입력을 신뢰할 수 없는 데이터로 다룹니다. 개인·민감 정보는 샘플 데이터에 사용하지 말고, 오류 응답에 비밀값이나 원문 전체를 포함하지 않습니다.
