미션의 목적

흩어진 프롬프트를 다루는 콘솔 프로그램을 Python으로 만들며, 기초 문법을 실제 기능에 연결하고 Git으로 작업 이력을 남깁니다. 목표는 단순히 코드를 완성하는 것이 아니라 작동 원리와 변경 이력을 설명할 수 있는 것입니다.

완료 후 학습자가 할 수 있어야 하는 것
VS Code에서 Python 프로그램을 실행하고, 자료구조·함수·반복문을 설명하며, Git 브랜치를 이용해 작업하고 GitHub에 결과를 게시합니다.
1. 개발 환경 확인

Python 3.10+, VS Code, Git, GitHub 연결을 확인

2. 저장소 시작

GitHub 저장소와 로컬 저장소를 연결하고 첫 커밋·푸시

3. Python 프로그램 구현

리스트·딕셔너리와 함수로 프롬프트 관리 기능을 순차 구현

4. 기능 브랜치 병합

목록 기능을 별도 브랜치에서 만들고 main에 병합

5. 검증·문서화·제출

10개 이상 기능 단위 커밋, README, 실행 및 Git 이력 증빙

필수 기능 범위

  • 프롬프트 추가 및 빈 입력 검증
  • 전체 목록, 카테고리별 조회, 키워드 검색
  • 번호를 이용한 상세 보기
  • 즐겨찾기 추가·해제 및 즐겨찾기 목록
  • 잘못된 메뉴·번호 입력 안내 후 메뉴로 복귀

핵심 제약과 범위

  • 필수 기능은 Python 기본 문법으로 구현
  • 이전 미션의 프롬프트 3개 이상을 기본 데이터로 준비
  • 데이터는 실행 중 유지하고, 종료 시 초기화해도 됨
  • 최소 10개 의미 있는 커밋과 브랜치 생성·병합
  • 선택 JSON 영속화·CRUD·사용 기록
퍼실리테이터 포인트
Git 명령 횟수만 채우는 데서 끝나지 않도록 합니다. 학습자가 각 커밋의 변경 의도와 브랜치를 나눈 이유를 자기 말로 설명하는지 확인하세요.

의존성 기반 실행 계획

정해진 시간은 없으므로 학습자 속도에 맞춰 쪼개세요. 한 번에 완성 코드를 제공하기보다 작은 실행 가능한 단위마다 확인합니다.

단계 1 · 환경 준비

Python 3.10 이상, Git 버전·사용자 정보, VS Code 실행, GitHub 로그인 확인. 검증: Hello 출력과 버전 화면을 확인합니다.

단계 2 · 저장소와 첫 커밋

GitHub 저장소 생성, 로컬 폴더 초기화, .gitignore·README 작성, 원격 연결 후 push. 공개 샘플 저장소를 clone해 구조와 log도 살펴봅니다.

단계 3 · 데이터와 메뉴

기본 프롬프트 3개 이상을 리스트 안 딕셔너리로 표현하고, 메뉴 반복·종료·잘못된 입력 처리를 만듭니다. 각 작은 기능을 실행해 확인합니다.

단계 4 · 프롬프트 기능 구현

추가 → 전체 목록(기능 브랜치) → 카테고리 → 검색 → 상세 보기 → 즐겨찾기 순으로 구현합니다. 각 기능에서 정상·경계 입력을 시험합니다.

단계 5 · 병합과 제출

목록 기능 브랜치를 커밋하고 main에 merge합니다. README, 저장소 공개 상태, 커밋 그래프와 실행 화면 증빙을 최종 점검합니다.

구현 순서를 정하는 기준

메뉴와 데이터가 기능들의 공통 기반입니다. 먼저 프로그램이 실행되고 데이터에 접근하는 흐름을 만든 다음, 데이터를 읽는 기능에서 데이터를 바꾸는 기능으로 확장합니다.

매 단계의 완료 기준은 “코드가 있음”이 아니라 “실행 결과를 확인했고, 학습자가 그 동작을 설명함”입니다.

권장 기능 단위 커밋 예

feat: add initial prompt data
feat: add menu loop and exit option
feat: validate prompt inputs
feat: implement category filtering
docs: add setup and usage guide

예시는 방향을 보여주는 용도입니다. 실제 커밋 메시지는 학습자가 변경 내용에 맞춰 작성하도록 합니다.

지식 · 공부해야 할 것

  • Python 실행과 터미널에서 버전 확인 — 환경을 스스로 점검하기 위해
  • 변수·문자열·조건문·while 반복 — 메뉴와 사용자 입력 흐름 구성에 사용
  • 리스트·딕셔너리 — 여러 프롬프트와 각 항목 속성을 표현

  • Git의 저장소·스테이징·커밋·브랜치·병합 — 변경을 안전하게 기록하고 통합
  • GitHub 원격 저장소와 clone/push/pull — 로컬 작업을 원격과 주고받음

기술 · 할 수 있어야 할 것

  • 현재 데이터가 종료 후 사라지는 이유와 JSON 저장이 추가하는 설계

검색어가 제목에는 없고 내용에만 있을 때도 결과가 나오게 하려면 어떤 조건이 필요할까요?
프로그램이 메뉴를 다시 보여주는 조건과 종료하는 조건은 각각 무엇인가요?
목록 기능을 별도 브랜치에서 개발한 이유와 병합 후 확인할 것은 무엇인가요?
실행을 종료한 뒤에도 데이터가 남게 하려면 현재 프로그램에 무엇이 더 필요할까요?

학습자 주도 퍼실리테이션

질문 → 학습자 설명 → 작은 실험 → 실행 결과 확인 순으로 진행합니다. 막히면 답을 먼저 주기보다 문제를 더 작게 쪼개고 다음 행동을 선택하게 합니다.

시작 전 · 경험과 목표 연결하기
“프롬프트를 잃어버리거나 다시 찾느라 불편했던 순간이 있었나요?”
“이번 프로그램에서 가장 먼저 쓰고 싶은 기능은 무엇이고, 어떤 데이터가 필요할까요?”

유도 방향: 실사용 상황에서 기능 요구를 뽑고, 이전 미션 프롬프트 3개를 예시 데이터로 가져오게 합니다.

환경·Git · 도구의 상태를 스스로 확인하게 하기
“Python과 Git이 설치되어 있다는 것을 어떤 명령과 결과로 확인할 수 있나요?”
“파일을 수정한 것과 그 변경을 커밋한 것은 어떻게 다른가요?”

유도 방향: 화면을 대신 조작하지 않고 학습자가 직접 버전·설정을 확인합니다. 계정 정보나 이메일은 화면 공유 시 노출하지 않도록 안내합니다.

자료구조·함수 · 코드를 말로 모델링하기
“프롬프트 한 건에 필요한 정보는 무엇이고, 여러 건은 어떻게 묶어 둘까요?”
“목록 출력과 검색이 같은 데이터에서 시작하는 이유는 무엇인가요?”

유도 방향: 제목·내용·카테고리·즐겨찾기 필드를 학습자가 정의하도록 합니다. 리스트와 딕셔너리의 역할을 실제 데이터 예시로 구분합니다.

디버깅 · 오류 메시지를 관찰 가능한 단서로 바꾸기
“오류가 처음 발생한 줄은 어디이며, 그 순간 변수에 어떤 값이 들어 있나요?”
“문제를 재현하는 가장 짧은 입력은 무엇이고, 한 번에 하나만 바꿔서 확인할 수 있나요?”

유도 방향: 에러 전문 확인 → 입력·변수 확인 → 최소 재현 → 수정 후 동일 입력 재시험. 원인을 말로 설명하기 전에는 큰 코드 재작성으로 넘어가지 않습니다.

회고 · 기능과 이력을 설명하게 하기
“가장 의미 있었던 커밋은 무엇이며, 그 커밋 전후에 무엇이 달라졌나요?”
“병합 후 목록 기능이 main에서도 동작하는 것을 어떻게 확인했나요?”

유도 방향: 시연과 설명을 함께 평가하고, 다음 단계의 확장(파일 저장·수정/삭제)을 지금 필수 범위와 구분하도록 합니다.

막힘 수준별 개입

막힘목표를 한 동작으로 축소하고 입력·기대 결과를 말하게 합니다.

잘못된 번호에서 인덱스 오류입력 범위 검증이 리스트 접근보다 먼저인지“리스트에 접근하기 전 유효한 번호를 확인하나요?”

push/merge 거부 또는 충돌현재 브랜치, 원격 변경, 충돌 파일과 표시 구간“어떤 변경이 겹쳤는지 확인하고, 해결 후 무엇으로 검증할까요?”
실행 종료 후 데이터가 사라짐요구사항상 정상 동작인지, 보너스 영속화인지“필수 요구와 선택 보너스의 범위를 구분해 볼까요?”
설계 질문은 평가 기준과 분리
중복 제목 처리, 저장 파일 형식, 카테고리 확장 등 명세에 규칙이 고정되지 않은 부분은 한 가지 답을 강요하지 않습니다. 학습자가 선택한 규칙과 이유를 설명하는지 확인합니다.
