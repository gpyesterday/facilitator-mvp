미션 1

질문하며 기획하고 HTML 첫 버전 만들기

미션 소개: '영화 티어리스트를 만들고 싶다'는 아이디어에서 시작합니다. AI에게 바로 만들게 하지 않고 필요한 것을 먼저 질문하게 합니다. AI가 답한 내용을 기획서.md로 정리하고, 그 기획서로 HTML 한 장을 만들어 직접 열어 보고, 다른 AI에게도 같은 기획서를 줘서 결과를 비교합니다.

1
AI가 먼저 질문하게 합니다.아이디어.md를 첨부하거나 붙여 넣고 '영화 티어리스트 웹페이지를 만들고 싶어. 아직 만들지 말고 필요한 것부터 질문해 줘.'라고 요청합니다.
2
답변을 기획서로 정리합니다.대화 내용을 바탕으로 '누가 쓰나 / 무엇을 하려고 / 화면과 동작 / 필요한 자료 / 완성 기준' 다섯 항목으로 기획서.md를 작성합니다.
3
기획서로 HTML을 만듭니다.HTML·CSS·JavaScript가 모두 들어 있는 HTML 파일 하나를 만들어 외부 파일이나 서버 없이 브라우저에서 바로 열리게 합니다.
4
파일로 열어 기획서와 비교합니다.영화_A_초안.html로 저장해 브라우저에서 열고, 완성 기준을 하나씩 직접 해 봅니다.
5
다른 AI에도 같은 기획서를 줘 봅니다.회사가 다른 AI 모델의 새 대화창에 같은 기획서.md와 요청을 줍니다. 받은 파일은 영화_B_초안.html로 저장합니다.
6
고른 결과물에 문제가 있다면 고칩니다.기획서와 다른 부분이 있다면, 해당 파일을 만든 AI에게 수정을 요청합니다.

미션 2

오류를 재현하고, 본 대로 물어서 고치기

미션 소개: 제공된 영화 티어리스트에는 기획서대로 되지 않는 곳이 있습니다. 직접 써 보며 찾고, 어떤 경우에 생기는지 좁혀 한 문장으로 적습니다. 그 문장으로 AI에게 원인부터 묻고, 그 문제만 고친 뒤 같은 방법으로 다시 확인합니다.

1
원본을 보관합니다.영화_수정전.html은 덮어쓰지 않고, 고친 파일은 새 이름으로 저장합니다.
2
기획서대로 써 보며 안 되는 곳을 찾습니다.파일을 열고 '처음으로'를 누른 뒤, 기획서.md의 완성 기준을 하나씩 해 봅니다. 영화 8개는 하나도 빼지 않고 옮겨 봅니다.
3
어떤 경우에 생기는지 좁힙니다.안 되는 곳을 찾으면 바로 묻지 말고 먼저 따져 봅니다. 같은 행동을 다시 해도 매번 그런가? 되는 영화와 안 되는 영화는 무엇이 다른가? 누르기와 끌어 놓기 둘 다 안 되는가? 직접 추가한 영화도 그런가?
4
바로 고치게 하지 않고 원인부터 묻습니다.기획서.md와 영화_수정전.html을 첨부하거나 붙여 넣고 요청합니다. '어떻게 했는지 / 원래 어떻게 되어야 하는지 / 실제로 어떻게 됐는지 / 되는 경우와 안 되는 경우의 차이'를 포함합니다.
5
그 문제만 고치게 합니다.'이 문제만 고쳐 줘. 다른 기능과 화면은 그대로 두고, 바꾼 곳을 쉬운 말로 설명해 줘.'라고 요청합니다. 수정한 HTML 전체를 줍니다.
6
같은 방법으로 다시 확인합니다.받은 파일을 영화_수정1.html로 저장해 열고 먼저 '처음으로'를 누릅니다. 안 됐던 영화와 추가한 영화를 같은 방법으로 다시 옮겨 봅니다.

미션 3

직접 써보고 피드백 주고받기

미션 소개: 민수 님은 영화 티어리스트를 만든 뒤 피드백을 두 가지 받았습니다. AI 검토와 동료 피드백입니다. 페이지를 직접 써 보며 각 피드백이 맞는지, 민수 님께 도움이 되는지 확인합니다. 그 다음 민수 님 입장에서 무엇을 반영할지 정하고, 받은 피드백을 민수 님께 정말 도움이 되는 피드백 하나로 다시 씁니다.

1
먼저 직접 써 봅니다.받은_피드백.md는 아직 열지 않습니다. 민수_기획서.md를 읽고 민수_영화티어리스트.html을 열어 완성 기준을 하나씩 해 봅니다.
2
받은 피드백을 직접 확인합니다.이제 받은_피드백.md를 엽니다. 피드백에서 말한 것을 하나씩 직접 해 보고, 실제로 어땠는지 기록에 적습니다. AI 검토도 동료 의견과 똑같이 확인합니다.
3
민수 님 입장에서 정합니다.같은 표에 의견마다 반영·보류·되묻기 중 하나를 고르고 이유를 적습니다. 되묻기라면 무엇을 물을지 적습니다.
4
민수 님께 보낼 피드백을 씁니다.잘된 점, 고치면 좋을 점(본 것·기준·제안)으로 피드백.md로 저장합니다.

기능을 더하고 확인·복구를 반복하기

미션 소개: 잘 동작하는 영화 티어리스트에 내가 고른 기능 하나를 AI로 더합니다. 예를 들어 칸마다 영화 개수 보여 주기, 제목으로 영화 찾기, 카드에 한 줄 메모 달기, 칸 이름 바꾸기 같은 기능입니다. 새 기능과 함께 원래 기능도 직접 확인하고, 망가졌으면 원래 파일로 돌아가 다시 요청합니다.

1
원본 파일을 써 봅니다.영화_원본.html을 열고 기획서.md의 완성 기준대로 되는지 하나씩 해 봅니다. 이 파일은 고치지 않고 그대로 둡니다.
2
더할 기능을 정합니다.기능을 하나 고르고, 무엇을 했을 때 어떻게 되면 성공인지 기획서.md의 완성 기준 끝에 덧붙입니다.
3
AI에게 기능을 더해 달라고 합니다.영화_원본.html과 기획서.md를 첨부하거나 붙여 넣고 요청합니다. '첨부한 기획서의 완성 기준이 모두 맞아야 해. 원래 기능은 바꾸지 마. 수정한 HTML 전체를 줘.'
4
받은 파일을 완성 기준으로 확인합니다.받은 파일은 원본을 덮어쓰지 않고 영화_기능추가.html로 저장합니다. 열어서 완성 기준을 처음부터 하나씩 해 봅니다.
5
원래 기능이 망가졌으면 원래 파일로 돌아갑니다.망가진 파일을 계속 고쳐 달라고 하지 않습니다. 영화_원본.html을 가지고 새 대화에서 다시 요청합니다.

세미나 1

AI와 함께 HTML 페이지 기획서 작성하기

미션 소개: 브라우저에서 보는 웹 페이지는 HTML로 작성됩니다. AI에게 제작을 요청하려면 어떤 페이지를 원하는지 구체적으로 설명해야 합니다. AI의 질문에 답하며 대상 사용자, 사용 목적, 화면 구성과 동작을 구체화하고, 기획서로 정리합니다.

최종 결과물

다음 내용을 포함한 기획서.md 파일 1개를 제출합니다.

  • 기본 항목 5개: 대상 사용자, 사용 목적, 화면 구성과 동작, 필요한 자료, 완료 기준
  • 필수 기능과 추가 기능
  • 한계 및 비목표 3가지
  • 검증 방법 1가지
  • 사용한 AI 서비스와 모델 이름

과제 목표

  • 제작할 페이지의 목적과 기능을 기획서로 정리하고, 확인 가능한 완료 기준을 작성할 수 있다.
  • AI가 작성한 기획서를 검토하고 의도와 다른 내용을 수정할 수 있다.
  • 필수 기능과 추가 기능을 구분할 수 있다.
  • 구현 범위에서 제외할 기능과 페이지의 한계를 정리하고, 결과의 정확성을 확인할 검증 방법을 정할 수 있다.
  • 동료의 기획서를 읽고 근거를 제시하여 평가할 수 있다.

제약 사항

  • 제출물은 기획서.md 파일 1개로 한정합니다. HTML 구현은 후속 미션에서 진행합니다.
  • 로그인, API 키, 서버가 필요한 기능과 챗봇·AI 기능은 포함하지 않는 것을 권장합니다.
  • 외부 자료(사진·글·글꼴·라이브러리)를 활용할 계획이라면 '필요한 자료'에 출처와 사용 권한을 명시합니다. 사진은 https://로 시작하는 인터넷 주소로 삽입합니다.
세미나 2

두 AI로 HTML 만들고 테스트하기

미션 소개: 기획서에 정리한 구상이 실제 화면으로 구현되면, 글로만 읽을 때는 알기 어려웠던 차이가 드러납니다. 같은 기획서를 두 AI에게 동일하게 전달해 각각 HTML 페이지를 제작하고, 두 결과를 같은 방법으로 테스트한 뒤 하나를 선택합니다. 선택 근거와 테스트 결과를 기록합니다.

최종 결과물

  • HTML 파일 1개: 두 AI의 결과 중 선택한 HTML 파일입니다. 페이지_v1.html처럼 버전을 표시한 파일 이름으로 정합니다.
  • 제작검증기록.md: 두 AI의 서비스·모델 이름, 전달한 요청, 각 결과의 비교 내용과 선택 근거, 선택한 HTML의 테스트 결과 3건을 기록합니다.

과제 목표

  • 같은 기획서로 제작한 두 AI의 결과를 비교하고, 선택 근거를 설명할 수 있다.
  • AI가 생성한 HTML을 브라우저에서 열고, 완료 기준에 따라 동작을 테스트할 수 있다.
  • 테스트 내용, 예상 결과, 실제 결과를 구분하여 기록할 수 있다.
  • 화면 너비, 입력값, 인쇄 등 조건을 변경하여 테스트할 수 있다.

제약 사항

  • HTML은 파일 1개로 구성합니다. CSS와 필요한 JavaScript를 같은 파일에 포함합니다.
  • 로그인, API 키, 서버가 필요한 기능과 챗봇·AI 기능은 추가 기능으로 분류하고, 이번 제작 요청에서는 제외합니다.
  • 사진은 로컬 파일 대신 https://로 시작하는 인터넷 주소로 삽입합니다.
  • 두 AI에 동일한 기획서와 요청을 전달합니다. 한쪽에만 추가 요청을 전달하지 않습니다.
세미나 3

테스트하며 고치고 사용자 피드백 반영하기

미션 소개: 직접 만든 페이지는 기능이 어디에 있고 어떻게 사용하는지 이미 알고 있어, 처음 사용하는 사람이 겪을 어려움을 놓치기 쉽습니다. 실제 사용 과정을 관찰하면 어떤 부분을 개선해야 하는지 구체적으로 확인할 수 있습니다. 발견한 문제를 AI에게 전달할 때는 관찰한 내용이 중요합니다. 수정한 뒤에는 같은 테스트를 반복하여 문제가 해결되었는지 확인하고, 기존 기능도 함께 점검합니다.

최종 결과물

  • HTML 파일 1개: 수정과 사용자 피드백을 반영한 최종 버전입니다.
  • 기획서.md: 최종 HTML에 맞게 수정한 기획서입니다.
  • 제작검증기록.md: 이전 미션의 두 AI 비교 기록과 테스트 3건, 수정 기록 3건, 사용자 1명의 피드백과 반영 결과를 기록합니다.

과제 목표

  • 직접 테스트하여 문제를 발견하고, 추측한 원인 대신 관찰한 현상을 AI에게 설명하여 수정을 요청할 수 있다.
  • 한 번에 하나씩 수정하고 버전별로 저장하며, 기존 기능의 정상 동작 여부를 다시 확인할 수 있다.
  • 사용자의 행동과 피드백을 근거로 페이지를 개선할 수 있다.
  • 기획서를 최종 HTML에 맞게 수정할 수 있다.

제약 사항

  • HTML은 파일 1개로 구성합니다. CSS와 필요한 JavaScript를 같은 파일에 포함합니다.
  • 로그인, API 키, 서버가 필요한 기능과 챗봇·AI 기능은 추가 기능으로 분류하고, 해당 기능 없이도 페이지가 열리고 동작하도록 합니다.
  • 사진은 로컬 파일 대신 https://로 시작하는 인터넷 주소로 삽입합니다.
