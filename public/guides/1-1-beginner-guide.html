1먼저 이것만 알고 시작하세요

미션 전체에서 "당신이 직접 해야 하는 판단"은 딱 네 가지입니다. 나머지는 AI가 도와줘도 됩니다.

직접 써야 하는 판단 4종 (AI 대행 금지) ① 모델을 고른 이유  ② 프롬프트를 수정한 이유
③ 어느 과업에서 막혔는지  ④ 환각 검증의 Pass / Fail 판정
이 네 개를 AI가 대신 쓰면 미션에서 확인하려는 "판단 과정"이 사라져 요구사항 위반입니다.
AI에게 맡겨도 되는 일 프롬프트 초안 다듬기, 표 정리, 문장 교정, 마크다운 형식 맞추기, Few-shot 예시 문장 만들기, 대화 로그 오타 정리(단, 생성 결과 본문은 편집 금지).
제일 중요한 규칙 하나 대화 로그는 편집하지 않고 그대로 남깁니다. 화자 표기(User: / AI:)와 지점 표시만 덧붙일 수 있습니다. 로그를 예쁘게 고치면 검증 요구 전체가 성립하지 않습니다.

2용어 7개만 잡으면 과제가 보입니다

컴퓨터 지식이 아니라 어휘 문제입니다. 아래 7개를 자기 말로 설명할 수 있으면 문서가 읽힙니다.

① 시스템 프롬프트

AI에게 미리 주는 성격과 규칙. 매번 다시 말하지 않아도 계속 적용됩니다.

예: "너는 회의 서기다. 없는 정보는 만들지 마라."

② 유저 프롬프트

내가 그때그때 입력하는 이번 작업 지시.

예: "이 회의록에서 결정 사항만 3줄로 뽑아줘."

③ 입력 템플릿

빈칸만 채워 복사해 다시 쓰는 양식. 이 미션은 1개 이상 필수입니다.

예: 회의록: {원문} / 기준: {조건} / 출력: 3줄

④ Zero-shot

예시 없이 한 번에 시키기. 결과가 들쭉날쭉합니다.

예: "회의록 요약해 줘."

⑤ Few-shot

입력→출력 예시를 몇 개 보여주고 시키기. 형식이 안정됩니다. 3건 이상 필수.

예: 입력 "…" → 출력 "…" 를 3쌍 제시

⑥ 단계적 추론 유도

"먼저 A 하고, 그다음 B 하고, 마지막에 C"처럼 순서를 정해 주는 것. v2 개선에 쓰면 좋습니다.

예: 1) 분류 2) 부족하면 질문 3) 템플릿 출력

⑦ 환각 / 문맥 끊김

환각 = 사실과 다른 대답. 문맥 끊김 = 앞에서 준 조건을 뒤 턴에서 잊는 것.

환각: 없는 날짜를 만들어 씀 / 문맥: 3줄로 하라 했는데 5줄로 씀

＋ 헷갈리기 쉬운 것

환각 ≠ 창의적 글쓰기. 상상해서 쓴 소설은 환각이 아닙니다. "사실인데 틀린 것"만 환각입니다.

1턴 = 발화 하나. User 5번 + AI 5번 = 10턴

8막힐 때 FAQ

실제로 가장 많이 나오는 질문들입니다. 접어두었으니 필요한 것만 펼쳐 보세요.

시스템 프롬프트를 어디에 넣어야 하나요?
서비스마다 위치가 다릅니다. ChatGPT는 설정의 '사용자 지정 지침', Claude는 '프로젝트 지침', Gemini는 'Gem'입니다. 찾다가 시간을 다 쓰는 경우가 많으니, 미션에서 허용된 대화 첫 메시지로 넣는 방식을 쓰세요. 첫 메시지에 시스템 프롬프트를 붙이고, 그다음부터 과업 대화를 시작하면 됩니다. 로그에도 그대로 남습니다.
무료 모델만 있어도 되나요?
됩니다. 오히려 세 종 중 하나 이상은 무료 요금제여야 한다는 조건이 있으니 무료 모델이 필요합니다. 주의할 점은 무료 한도입니다. 모델 비교는 짧은 입력으로 하고, 10턴 대화는 한도가 넉넉한 모델로 하세요. 대화 도중 한도가 소진되면 로그가 끊기므로, 넉넉한 모델을 먼저 확인하는 게 좋습니다.
같은 입력을 두 번 넣었는데 답이 달라요. 실패인가요?
아닙니다. 정상이고, 그게 관찰 결과입니다. LLM은 확률적으로 문장을 생성하므로 같은 입력에도 결과가 달라질 수 있습니다. "동일 입력 2회에서 A는 같았고 B는 3줄이 5줄로 늘었다"처럼 무엇이 같고 무엇이 달랐는지를 적으면 그대로 요구사항 충족입니다.
10턴이 User 10번인가요, User+AI 합쳐서인가요?
발화 하나가 1턴입니다. 그래서 User 5번 + AI 5번 = 10턴입니다. 여유 있게 12~14턴 정도 만들면 조건 변경·반복 확인을 넣어도 10턴을 넘깁니다.
환각이 하나도 안 나왔어요. 어떻게 하죠?
그럴 수 있습니다. 미션도 "둘 다 나타나지 않았으면 나타나지 않았다고 적어도 충족"이라고 명시합니다. 다만 그 경우 v2 수정 근거는 지시와 가장 어긋난 응답 1개를 골라 그것을 고치는 수정으로 잡아야 합니다. 그래서 대화 중 "이건 좀 어긋났다" 싶은 응답은 미리 메모해 두세요.
Pass/Fail 판정 기준이 두 개라는데, 둘 다 맞아야 하나요?
아닙니다. 하나만 충족해도 Pass입니다. 기준 A = 정답을 맞히고 근거를 함께 제시. 기준 B = 모를 때 "모른다" 또는 "확인 필요"를 밝히고 확인 절차를 제안. 둘 다 못 하면 Fail입니다. 이걸 모르면 전부 Fail로 적게 됩니다.
미해결 기록에 뭘 써야 하나요? 다 성공했는데요.
실제로 하다 보면 됩니다. 안 되면 그게 미해결입니다. 억지로 만들 필요는 없지만, "완벽하게 못 한 것"을 실패로 인정하기 어려워 여기서 많이 멈춥니다. 본인 잘못이 아니라 모델이나 프롬프트의 한계로 적으면 됩니다. 원인을 정확히 몰라도 "무엇을 시도했고 어디서 멈췄는지"가 있으면 충족입니다. 성공한 시도는 쓰지 마세요.
회사 업무 자료를 넣어도 되나요?
안 됩니다. 개인정보와 사내 기밀은 상용 AI에 입력 금지입니다. 공개 보도자료, 정부 보도자료, 위키 문서, 또는 직접 만든 가상 회의록으로 대체하세요. 과업의 형식만 유지하면 되므로 실제 회사 자료일 필요는 없습니다.
보너스 과제는 꼭 해야 하나요?
아닙니다. 게다가 3개를 모두 완료해야만 크레딧이 지급됩니다(부분 점수 없음). 3번(Google Apps Script + API 키)이 비전공자에게 가장 어렵습니다. 다만 "결제수단 문제로 키를 발급하지 못해도 그 사실을 적으면 충족", "다른 도구로 수행해도 되고 바꾼 이유를 적으면 충족"이라는 탈출구가 있습니다. 본편 4개 문서를 끝낸 뒤 여유가 있을 때만 손대세요.
소요 시간이 얼마나 걸릴까요?
퍼실리테이션 가이드는 5시간으로 잡지만, 비전공자는 8~12시간으로 보는 게 현실적입니다. 가장 오래 걸리는 구간은 ①환각 검증 Pass/Fail 판정 ②Few-shot 되묻기 예시 ③GitHub 업로드입니다. 반대로 10턴 대화와 프롬프트 작성은 생각보다 빨리 끝납니다.
미션 문서를 읽다가 헷갈리는 지점 mission_details.md의 요구사항에는 번호가 없는데 본문은 "요구사항 6", "요구사항 8"처럼 계속 참조합니다. 위에서부터 1. 과업 선정 / 2. 모델 3종 비교 / 3. 페르소나 설계 / 4. 프롬프트와 예시 작성 / 5. 대화 수행과 작업 기록 / 6. 검증 전략과 환각 검증 / 7. 로그 지점 표시 / 8. 프롬프트 개선과 카테고리 / 9. 미해결 기록 으로 세면 맞습니다. 또한 guide.html은 "결과물 3종"이라고 쓰지만 실제 산출물은 4종입니다. 4종을 기준으로 하세요.
