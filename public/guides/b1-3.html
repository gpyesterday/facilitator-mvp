B1-3: 노코드 자동화 기초 - 워크플로우 설계

퍼실리테이션 인터랙티브 가이드 | AI 도구 | 선택 심화 | 난이도: 2

🎯 미션 핵심 목표

Trigger(시작 이벤트) → Action(처리 동작) → Filter/Router(조건 분기)로 이어지는 노코드 자동화 워크플로우를 설계·구현하는 역량을 기른다.

Make(또는 Zapier) 같은 플랫폼은 코딩 없이 시각적으로 Trigger와 Action을 연결해 반복 업무를 자동화합니다. 이번 미션에서는 동일한 워크플로우를 2개 이상의 도구로 구현하고 비교 분석한 뒤, 자유 주제로 나만의 자동화 파이프라인을 설계·구현합니다. 단순히 "돌아가기만 하면 된다"가 아니라 왜 그렇게 설계했는지 설명하는 것이 핵심입니다.

Step 1: 워크플로 정의

자동화할 반복 업무 정의 → Trigger/Action/Filter 식별 → 흐름도 작성

Step 2: 도구 1 구현

Make 또는 Zapier로 워크플로우 구현 → 스크린샷 캡처

Step 3: 도구 2 구현

동일 워크플로우를 다른 도구로 재구현 → 스크린샷 캡처

Step 4: 비교 분석

최소 5개 항목 비교 → 장단점 정리 → 보고서 작성(Markdown/PDF)

Step 5: 자유 주제 구현

개인 업무 자동화 설계 → 1도구로 구현 → 실행 결과 검증

Step 6: 제출 검수

스크린샷/문서/링크에서 민감정보 마스킹 확인 → 2종 결과물 제출

📦 최종 결과물 2종

1. 프로젝트 1: 자동화 도구 비교 구현

동일 워크플로우 2도구 구현(구성 스크린샷 + 실행 결과 스크린샷) + 비교 분석 보고서(PDF/Markdown)

2. 프로젝트 2: 자유 주제 자동화 설계 및 구현

반복 업무 정의 + 도구 선정 이유 + 워크플로 설계 문서(설명/다이어그램) + 구현 스크린샷 + 실행 결과 스크린샷

💡 핵심 관점
Trigger/Action/Filter가 왜 그렇게 연결됐는지를 설계 단계부터 기록해야 합니다. 단순히 화면을 연결한 것이 아니라, 왜 이 도구를, 왜 이 순서로, 왜 이 조건으로 분기했는지를 근거 있게 설명할 수 있어야 합니다.

📋 핵심 체크 포인트
• 설계 설명은 "순서"뿐 아니라 왜 그 순서인지(예: 이미지→영상 변환으로 크레딧 절약)를 들어야 합니다.
• 대체 도구는 각 Action마다 1개 이상 준비해 두는 것이 안전합니다.
• 분기 실행 결과는 로그 히스토리 스크린샷으로 증명해야 합니다.

  • 비교한 도구들의 차이를 "업무 요구사항" 관점으로 연결해 설명할 수 있는가(예: 협업/운영/디버깅/확장/비용)?
  • 프로젝트 2에서 특정 도구를 선택한 이유를 비교 항목 2개 이상과 연결해 설명할 수 있는가?
  • Filter와 Router의 차이와 언제 각각을 사용했는지 설명할 수 있는가?

Q1: "같은 워크플로우를 다른 도구로 만들면 무엇이 가장 달라질까요?"
• UI/UX: Make은 시각적 노드 기반 / Zapier는 리스트 기반 (학습 곡선 차이)

• 실행 로그: Make은 단계별 데이터 상세 확인 / Zapier는 Task History 제공

💬 학습자 돕기 (GAP 질문)

"Trigger와 Action의 차이가 뭐죠?"
Trigger는 "언제 시작할까?"를 결정하고, Action은 "무엇을 할까?"를 정합니다. 예를 들어 "Google Form이 제출될 때"가 Trigger이고, "그 결과를 Google Sheets에 기록한다"가 Action입니다. Trigger는 워크플로의 시작점이자 감시 대상이며, Action은 실제 처리 로직입니다.
"Filter와 Router는 어떻게 다른가요?"
Filter는 "통과시킬지 말지" 결정합니다(True/False, 1차 분기). Router는 "어디로 갈지" 라우팅합니다(다중 분기, N차 분기). 예를 들어 점수 ≥80이면 Slack 알림, <80이면 이메일로 가는 로직은 Router가 더 적합하고, "80점 이상인지"만 확인하는 것은 Filter입니다.
"왜 같은 워크플로를 두 도구로 만들나요?"
도구마다 장단점과 한계가 다르기 때문입니다. Make는 복잡한 다단계 워크플로에 강하지만 초기 학습 곡선이 있고, Zapier는 직관적이지만 복잡한 분기에는 한계가 있습니다. 같은 요구사항을 두 도구로 구현해 보면, 각 도구의 특성과 무료 플랜 한도를 몸으로 체험할 수 있습니다.
"무료 플랜으로 감당 안 되면 어떻게 해요?"
Workflow Complexity Validator로 먼저 요구사항을 검증하고, 워크플로를 단순화하거나 대체 도구로 전환하세요. n8n(무료 셀프 호스팅), 자가 호스팅 가능한 오픈소스 도구도 고려해보세요. 유료 결제가 불가피한 경우 "왜 불가피했는지"와 "무료 대안"을 보고서에 함께 정리하면 됩니다.

🔧 문제 해결 가이드 (FAQ)

Q1. Trigger가 자꾸 실패하거나 반응이 없어요
💡 대응 방법
• 권한 재확인: Google Form/Sheets/Slack 등 연결 앱의 권한을 재인증(re-authenticate)하세요.
• Trigger 조건 검토: 폴링 간격이 너무 길거나 조건이 맞지 않는지 확인(무료 플랜은 폴링 간격 제한 있음)
• 대체 Trigger: Webhook이나 Slack 명령으로 Trigger를 대체해 보세요.
• 실행 로그: 도구의 실행 히스토리에서 정확한 오류 메시지를 확인하고, 그대로 검색하거나 팀에 문의하세요.
Q2. 분기(Filter/Router)가 실행되지 않아요
✅ 해결 방법
• 조건 데이터 타입 확인: 문자열 "80"과 숫자 80이 다를 수 있음. 타입 변환 액션을 추가하세요.
• 분기 실행 테스트: 실제로 분기에 들어가는 데이터(테스트 케이스)를 넣어 최소 1회 이상 실행 결과를 캡처하세요.
• 로그 확인: 분기 통과 여부는 실행 히스토리에서 "건너뛘" 또는 "통과" 로그로 확인 가능합니다.
Q3. 무료 플랜 한도(Ops/Tasks)를 초과했어요
💡 해결 전략
1. 워크플로 단순화: 불필요한 Action이나 분기를 제거하고 핵심 흐름만 유지
2. 대체 도구 전환: n8n(무료 셀프 호스팅)이나 다른 무료 플랜 도구로 마이그레이션
3. 스케줄링 최적화: 빈도를 일일 1회로 낮추거나, 필요할 때만 실행되도록 Trigger 조건을 좁힘
※ 유료 결제가 불가피한 경우 "왜 불가피했는지"와 "무료 대안"을 보고서에 함께 정리하세요.
Q4. 민감정보(토큰/키) 가 누출되었어요
⛔ 즉시 조치
• 해당 키/토큰을 즉시 무효화하고 새로 발급받으세요.
• 제출물(스크린샷/문서/링크)에서 값은 *** 처리하고, 계정 이메일도 일부 가려 주세요.
• Git 등에 커밋된 경우 GitHub의 BFG Repo-Cleaner 사용 가이드를 참고해 히스토리에서 제거하세요(워크스페이스 외 접근 금지).
Q5. 앱 연결이 자꾸 끊기거나 인증이 안 돼요
✅ 해결 방법
• 재인증: 연결된 앱의 OAuth 토큰을 만료시킨 후 다시 연결
• 대체 커넥터: 같은 서비스라도 다른 커넥터(예: Slack 대신 Discord Webhook)로 대체
• 계정 진입장벽: Google 앱 기반 서비스(Google Sheets + Gmail + Webhook) 조합이 진입이 쉽습니다.
