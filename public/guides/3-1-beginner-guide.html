"컴퓨터를 잘 못 다뤄도 끝낼 수 있나?" — 됩니다. 단, 순서를 지켜야 합니다. 이 미션의 진짜 벽은 코딩이 아니라 무료 요금제의 제약과 증빙 캡처 타이밍입니다. 도구를 고르기 전에 확인할 것, 실행 전에 캡처할 것을 이 페이지에서 먼저 정리합니다.

1먼저 이것만 알고 시작하세요

이 미션은 "코딩 없이 업무를 자동화하는 도구 두 개를 비교하고, 하나를 골라 실제로 돌려 보고, 못 만든 것을 기록하는" 과제입니다. 코드는 요구하지 않고, 코드 시도는 실패해도 요구사항이 충족됩니다.

직접 써야 하는 판단 4종 (AI 대행 금지) ① 도구를 고른 이유  ② 무엇이 왜 막혔는지(한계 기록)
③ 코드 시도에서 무엇을 판단했는지  ④ 분기를 어떤 기준으로 나눴는지
미션 문서가 명시한 조건입니다. 이 네 개를 AI가 대신 쓰면 "왜 그렇게 설계했는지"를 확인할 수 없어 감점됩니다. 평가 인터뷰에서도 그대로 물어봅니다.
AI에게 맡겨도 되는 일 워크플로우 설계 아이디어 묻기, 비교표 초안, 문서 문장 교정, 마크다운 정리, 막힌 기능의 코드 작성 요청.
단, 결과를 그대로 베끼지 말고 "내가 판단한 것"과 구분해서 쓰세요. 코드 요청 프롬프트는 산출물 3의 증빙이 되므로 반드시 남겨야 합니다.
제일 중요한 규칙 하나 — 캡처는 "나중에"가 아니라 "지금" 무료 요금제는 실행 횟수에 한도가 있습니다. 같은 워크플로우를 도구 2개로 만들면 실행 한도도 2배로 소모됩니다. 미션 문서도 "한도가 남아 있을 때 도구마다 먼저 캡처하라"고 경고합니다. 만들자마자 캡처하는 습관이 없으면 마지막에 증빙이 없습니다.

2용어 10개만 잡으면 과제가 보입니다

컴퓨터 지식이 아니라 어휘 문제입니다. 아래 10개를 자기 말로 설명할 수 있으면 문서가 읽힙니다. (평가 인터뷰에서 1·2·3번은 반드시 나옵니다)

① 트리거 (Trigger · 시작 조건)

"언제 자동화를 시작할까"를 정하는 것. 폼 제출, 새 메일 도착, 정해진 시간 등.

예: 구글 폼에 새 응답이 저장되었을 때

② 액션 (Action · 실행 동작)

"시작된 다음 무엇을 할까". 시트에 한 줄 추가, 메시지 보내기 등. 이 미션은 2개 이상 필요합니다.

예: 요약문을 시트에 한 줄 추가

③ 조건 분기 / Filter / Router

Filter = 통과시킬지 말지(2갈래). Router = 어디로 보낼지(여러 갈래). 이 미션은 1개 이상 + 경로마다 실행 증빙이 필요합니다.

예: 만족도 점수가 3점 이하인 응답과 나머지로 나눔

④ 생성형 AI 액션

워크플로우 안에서 AI가 분류·요약·문장 생성을 하는 단계. 이 미션의 필수 액션입니다.

예: 응답 내용을 한 문장으로 요약해 다음 단계로 넘김

⑤ 시나리오 / Zap / 워크플로우

도구마다 부르는 이름만 다르고 같은 뜻입니다. "트리거부터 마지막 액션까지 이어진 자동화 한 벌".

Make는 Scenario, Zapier는 Zap, n8n은 Workflow

⑥ 실행 1회 (Operation / Task / Execution)

액션 하나를 처리할 때마다 1회씩 차감되는 경우가 많습니다. 액션 3개짜리 워크플로우를 1번 돌리면 3회 소모일 수 있습니다.

무료 한도 예: 월 1,000회 / 월 100회 / 체험 기간제 — 도구마다 다름

⑦ 폴링 (주기 확인)

"새 메일 있나?"를 몇 분마다 물어보는 방식. 무료 요금제는 간격이 길어(예: 15분) 즉시 실행되지 않습니다.

반대말: 웹훅(Webhook) = 이벤트가 생기면 즉시 알려줌

⑧ 웹훅 (Webhook)

다른 서비스가 "지금 데이터 보냈어"라고 밀어주는 주소. 즉시 실행이 필요할 때 씁니다. 무료 플랜에서 막히는 경우가 있으니 확인 필요.

예: 설문 도구 → 웹훅 → 자동화 시작

⑨ 변수·필드 매핑 (이전 단계 값 넘기기)

앞 단계의 출력(예: AI 요약문)을 뒤 단계 입력칸에 꽂는 작업. 이게 이 미션의 핵심 증빙입니다.

예: AI 요약 → 시트의 "요약" 열에 매핑

⑩ API 키 / 실행 이력

API 키 = 외부 AI 서비스를 부를 때 쓰는 비밀번호 같은 문자열(캡처 시 반드시 가림). 실행 이력 = 각 실행이 성공·실패했고 단계별로 어떤 값이 오갔는지 보여주는 기록.

이력 화면이 곧 "자동으로 돌았다"는 증빙입니다
헷갈리기 쉬운 것 트리거 ≠ 액션 : 트리거는 "감시하다가 시작", 액션은 "시작된 뒤 처리". 트리거 자리에 시트 쓰기를 넣으면 그건 트리거가 아닙니다.
분기 ≠ 액션 : 분기는 처리하는 단계가 아니라 길을 나누는 단계입니다. 분기 블록에 실행 횟수가 잡히지 않는 도구도 있습니다.

3도구 고르기 — 여기서 실수하면 처음부터 다시 합니다

도구 이름보다 "무료로 트리거 1 + 액션 2 + 분기 1 + AI 액션 1이 되는가"가 중요합니다. 이걸 확인하지 않고 만들기 시작하면, 다 만든 뒤에 결제창을 만나게 됩니다.

도구를 정하기 전에 5분 안에 확인할 4가지

#확인 항목확인 방법
1다단계가 무료인가 무료 플랜에서 "트리거 1개 + 액션 2개"를 실제로 붙여 보고 저장이 되는지 확인. 2단계까지만 무료인 도구가 흔합니다.
2분기 블록이 무료인가 Filter / Router / Paths 블록을 추가해 보고 잠금 아이콘이 뜨는지 확인. 잠겨 있으면 프로젝트 1에서 그 도구를 쓰면 안 됩니다.
3AI 액션이 무료인가 + 키 필요 여부 AI 블록을 추가해 보고 (a) 무료 크레딧이 있는지 (b) 내 OpenAI 등의 API 키를 요구하는지 확인. 키를 요구하면 발급부터 해야 합니다.
4실행 한도가 내 횟수를 버티는가 액션 수 × 실행 횟수 × 도구 2개로 계산. 분기 양쪽을 만들려면 최소 4~6회는 돌려야 합니다.
요금제는 자주 바뀝니다 아래 표는 커리큘럼 가이드 기준입니다. 가이드 숫자를 믿지 말고 가입 화면의 요금제 안내를 직접 확인하세요. 숫자가 바뀌었다면 바뀐 값으로 보고서에 적으면 됩니다(오히려 좋은 비교 근거).
도구가이드 기준 무료 범위비전공자 관점 특징
Make 월 1,000 Ops 블록을 선으로 잇는 화면. 처음엔 낯설지만 한 번 익히면 다단계·분기가 편함. 1순위 추천
Zapier 월 100 Tasks 위에서 아래로 쌓는 화면. 가장 직관적이지만 무료는 단계 수 제한이 있어 분기·다단계가 막히는 경우가 많음. 분기 확인 필수
n8n 셀프 호스팅 무료 / 클라우드 체험 "무료"에 끌리기 쉽지만 셀프 호스팅은 Docker 설치·서버 운영이 필요. 컴퓨터 미숙자에게는 사실상 불가. 클라우드는 체험 기간 제한. 비추천
기타 도구별 커리큘럼은 Make/Zapier/n8n을 다루지만 다른 도구를 골라도 됩니다. 다만 위 4가지를 반드시 화면에서 확인.

Zapier 무료만으로 분기 포함 = 블록이 잠겨 프로젝트 1 재작업.
같은 도구의 요금제만 바꿔 2개 구현 = "도구 2개 비교"로 인정되기 어렵습니다.
무난한 출발 조합 ① Make(무료) + Zapier(무료) — 둘 다 Google 계정으로 시작, 비교 서사가 자연스러움
② Make(무료) + 다른 노코드 도구

5시나리오 고르기 — "내 업무"라고 생각하면 막힙니다

조건은 딱 두 개입니다. ① 반복된다 ② 판단 기준을 말로 쓸 수 있다. 회사 자료를 쓸 필요는 없습니다. 가짜 데이터로 같은 형식만 만들면 됩니다.

바로 쓸 수 있는 시나리오 예시

문의 메일 분류

새 메일 → AI가 문의/견적/광고로 분류 → 시트 기록 → 급한 건만 알림

설문 응답 정리

폼 응답 → AI 한 줄 요약 → 시트 누적 → 불만만 담당자 알림

리뷰 감정 분류

리뷰 등록 → AI가 긍정/부정 판정 → 부정만 별도 시트 + 알림

지원 접수 처리

신청 폼 → AI가 요약·우선순위 → 명단 시트 → 마감 임박 건 알림

일일 보고 수집

정해진 시간 → AI가 취합 요약 → 시트 기록 → 특이사항 알림

파일 이름 정리

업로드 감지 → AI가 분류 → 폴더 이동·시트 기록

절대 쓰면 안 되는 소재 실제 고객 메일, 고객 이름·연락처, 사내 미공개 자료는 자동화 대상으로 쓰지 않습니다(미션 제약사항). 데이터가 외부 서비스로 전송되는 구조이기 때문입니다. 내 메일함에 직접 만든 테스트 메일, 공개 자료, 가상 신청 폼으로 대체하세요.

테스트 데이터는 3종 세트로 미리 만들어 두세요

이걸 미리 안 만들어 두면 "분기 반대쪽을 어떻게 실행하지?"에서 멈춥니다. 가장 흔한 정체 구간입니다.

구분용도예시 (만족도 분기)
A. 조건 통과분기 한쪽 경로 실행만족도 2점 응답
B. 조건 미통과분기 반대쪽 경로 실행만족도 5점 응답
C. 경계값기준이 정확한지 확인만족도 3점 응답 (기준이 3 이하일 때)
경계값을 넣어 보면 좋은 것이 하나 더 있습니다 숫자 "3"과 문자 "3"이 다르게 판정되는 경우가 있습니다. 분기가 예상과 다르게 동작하면 거의 항상 데이터 타입 문제입니다. 이걸 발견하면 작업 기록에 "수정 1건"으로 남길 수 있습니다.

6캡처 순서 — 이 미션의 진짜 승부처

무료 한도는 되돌릴 수 없습니다. "다 만들고 나중에 캡처"는 가장 위험한 순서입니다. 아래 순서대로, 만드는 즉시 찍으세요.

순서캡처 대상왜 이 순서인가
1도구 A 구성 화면 (전체)아직 실행 0회. 실패해도 남길 수 있는 유일한 시점
2도구 A 실행 성공 + AI 출력값한도가 가장 넉넉할 때
