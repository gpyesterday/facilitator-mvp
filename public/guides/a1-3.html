A1-3: AI 도움을 받아 내 아이디어를 실제 웹사이트로 만들기

퍼실리테이션 인터랙티브 가이드 | AI 활용 미션 | 학습난이도: 3

🎯 미션의 핵심

학습자 자신의 아이디어를 바닐라 HTML/CSS/JavaScript와 Python 서버리스 함수로 구현하고, AI 기능을 연결해 Vercel URL로 공개합니다. AI 코딩 도구는 구현을 돕지만, 결과를 이해하고 오류를 진단하는 책임은 학습자에게 있습니다.

퍼실리테이터 관점의 성공 기준
기능을 많이 만드는 것보다, 사용자 문제 → 작동하는 최소 기능 → 검증 → 설명의 흐름을 학습자가 자기 말로 설명하도록 돕습니다.
1. 문제와 사용자 정의

누구의 어떤 불편을 해결하는지, 서비스가 제공할 가치를 좁힙니다.

2. 페이지와 AI 기능 설계

메뉴 이동이 가능한 페이지/섹션 3개 이상, AI 입력·출력·실패 기준을 정합니다.

3. 프론트엔드와 백엔드 구현

브라우저 화면과 Python API를 구분하고 fetch 요청·응답을 연결합니다.

4. 검증·배포·개선

로컬 및 배포 환경에서 기능을 확인하고, 문제를 고쳐 재배포합니다.

5. 문서화와 설명

필수 제출 패키지를 갖추고 코드·보안·오류 해결 과정을 설명합니다.

🧠 학습 목표 3가지

  • 지식
    웹의 역할 분담

    HTML 구조, CSS 표현, JavaScript 동작, Python API 역할을 구분한다.

  • 기술
    요청부터 배포까지 구현

    사용자 입력을 fetch로 전달하고, 응답·오류를 화면에 보여주며 Vercel에 배포한다.

  • 이해
    AI 코드의 검토자 되기

    생성 코드를 설명하고, 키 보호·테스트·디버깅이 필요한 이유를 말한다.

🧭 퍼실리테이션 원칙

먼저 작게: 하나의 사용자와 한 가지 핵심 과업으로 MVP를 정합니다.

한 번에 한 변화: AI에게 작은 작업을 요청하고 변경 결과를 실행해 확인합니다.

근거를 남기기: 오류 메시지, 재현 단계, 수정 내용을 기록하게 합니다.

비밀정보 보호: API 키는 환경 변수에 두며 코드·저장소·캡처에 노출하지 않습니다.

⚠️ 반드시 지킬 제약

프레임워크 및 API 키
프론트엔드는 순수 HTML/CSS/JavaScript로 구현합니다(React/Vue 등 사용 금지). AI API 키를 브라우저 코드에 넣지 말고, Python 서버리스 함수에서 환경 변수로 사용합니다.

배포 URL은 동료가 접근해 핵심 흐름을 재현할 수 있어야 합니다. 템플릿·예시는 복제하지 말고 학습자 아이디어에 맞게 바꿉니다.

5. 오류 진단오류 재현, 로그 확인, 원인 가설, 수정·재시험정답 코드를 바로 주기보다 “어디까지 됐고 어떤 응답을 받았나요?” 질문오류와 해결 기록
6. 배포·검증GitHub/Vercel 연동 후 공개 URL 테스트“로컬과 배포 환경에서 다른 설정은 무엇인가요?”배포 URL·테스트 결과
7. 정리·성찰README·기획서·증빙 정리 및 구조 설명평가 질문으로 이해도를 확인하고 다음 개선 하나를 정하게 함필수 제출 패키지

🪜 디버깅 순서

  1. 문제를 재현하고 기대 동작과 실제 동작을 적습니다.
  2. 브라우저 콘솔·Network·Vercel 로그에서 첫 오류를 찾습니다.
  3. 프론트 요청과 API 응답 중 어느 경계에서 실패하는지 구분합니다.
  4. AI에게 오류 전문과 관련 코드만 공유하고, 원인 가설을 설명하게 합니다.
  5. 작은 수정 하나를 적용하고 같은 시나리오로 다시 시험합니다.
  6. 로컬 및 배포 URL에서 회귀 확인 후 해결 과정을 기록합니다.

🔐 키 유출 의심 시

  1. 노출된 키를 즉시 폐기하고 새 키를 발급합니다.
  2. 서버/배포 환경 변수에 새 키를 설정하고 재배포합니다.
  3. 코드·로그·스크린샷에 새 키를 다시 노출하지 않았는지 확인합니다.
  4. 필요하면 저장소 이력과 제공자의 사용량을 점검합니다.
