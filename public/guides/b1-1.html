Step 1: LLM 3종 이상 비교·선정

Step 2: 페르소나 및 시스템 프롬프트 설계

안전장치·출력 규칙·사실 검증 규칙 포함

Step 3: Few-shot 예시 + v1→v2 개선

단계적 추론 유도 기법 적용 및 전후 비교

Step 4: 환할 검증 (5문제 이상)

Pass/Fail 기준 명확히 정의

Step 5: 10턴 이상 대화 로그

조건 변경·추가 정보 반영·문맥 유지 검증

완료! 결과물 3종 제출

🔍 평가질문 1: 기능 동작 검증

  • 업무 과업 1개가 문서에 명확히 정의됨 (타겟 사용자/입력/출력 규격 포함)
  • 입력 템플릿 1개 이상 제시 + 복사 가능한 재사용 형태
  • 3종 이상 모델 비교 결과 → 표 형식 (평가 축 4개+ / 점수 / 근거 포함)
  • Few-shot 예시 3개+ (1개는 "모호한 입력→되묻기" 포함)
  • 환할 검증 5문제+ / Pass-Fail 판정 결과 포함
  • 10턴 이상 대화 로그 / 중간 조건 변경 반영 확인 가능

🔍 평가질문 2: 동작 구조 및 설계

  • 시스템 프롬프트 / 유저 프롬프트 / 입력 템플릿이 명확히 분리되어 있음
  • 프롬프트 버전(v1→v2) 개선 과정 존재
  • 모델 비교는 주관적 인상평이 아니라 평가 축 기반 구조화
📋 핵심 체크 포인트
• 시스템 프롬프트는 "역할/목표/출력 규칙/안전장치/사실 처리 규칙"을 모두 포함해야 합니다.
• Few-shot 예시는 "좋은 입력 → 좋은 출력"을 보여야 하며, 모호한 입력 예시는 AI가 되물어야 하는 지점을 보여야 합니다.
• v1→v2 개선은 "일반 지시" → "단계적 추론 유도"로의 전환을 보여야 합니다.

🔍 평가질문 3: 핵심 기술 원리 적용

환할(Hallucination) 이해도
  • 환할을 "사실 오류"로 정의하고 창의적 생성과 구분함
  • Pass 기준(A/B)과 Fail 기준을 설명함
심층 인터뷰 대비
  • 무료 모델만 쓸 때 품질 유지 전략 설명 가능
  • 자주 바뀌는 정책으로 환할 억제 운영 전략 설명
  • 10턴 문맥 끊김 문제 대응 프롬프트 구조
💡 심층 인터뷰 질문 예시
